# VM Studio SEO Subpages Proposal

## Executive Summary

This proposal outlines a comprehensive SEO strategy to increase VM Studio's visibility through targeted subpages. Based on extensive research of keyword trends, competitor strategies, user personas, and content best practices, we recommend creating **15-20 strategic subpages** organized into 4 tiers of priority.

**Key Opportunity Areas:**
- Figma-specific AI image generation keywords (low competition, high relevance)
- Model comparison pages (high commercial intent)
- Use case pages for specific personas (designers, marketers)
- Feature-focused landing pages (text-to-image, image-to-image)

**Expected Impact:**
- Target 50+ long-tail keywords currently unaddressed
- Capture bottom-of-funnel comparison traffic
- Build topical authority in "AI image generation + Figma" niche

---

## Current State Analysis

### Existing Page Structure
VM Studio currently has a single-page website (`index.html`) covering:
- Hero section with value proposition
- Features bento grid (5 features)
- Models table (6 models, 4 providers)
- FAQ section (5 questions)
- CTA section

### SEO Gaps Identified
1. **No dedicated feature pages** - All features on one page dilutes keyword targeting
2. **No model-specific pages** - Missing opportunity for model comparison searches
3. **No use case content** - No pages targeting specific user personas
4. **No comparison content** - Missing bottom-of-funnel "vs" queries
5. **No tutorial/how-to content** - Missing informational intent searches
6. **No blog infrastructure** - No content cluster strategy

## Content Strategy

### Content Clusters (Hub and Spoke)

**Cluster 1: AI Image Generation in Figma**
- **Hub:** Homepage (vmstudio.ai)
- **Spokes:** /text-to-image, /image-to-image, /guides/getting-started

**Cluster 2: AI Models**
- **Hub:** /models
- **Spokes:** /models/flux, /models/nano-banana, /models/gpt-image, /compare/*

**Cluster 3: Use Cases**
- **Hub:** Features section on homepage
- **Spokes:** /use-cases/ui-ux-design, /use-cases/marketing, /use-cases/product-photography

**Cluster 4: Learning**
- **Hub:** /guides/getting-started
- **Spokes:** /guides/prompt-writing, /guides/api-keys, /gallery

### Internal Linking Strategy

1. **Homepage** links to all hub pages
2. **Hub pages** link to all their spokes
3. **Spokes** link back to hub and cross-link to related spokes
4. **All pages** have CTA linking to Figma plugin install
5. **Model pages** link to relevant use cases
6. **Use case pages** link to relevant model recommendations

## Technical SEO Requirements

### Per-Page Requirements

1. **Title Tag:** 50-60 characters, primary keyword first
2. **Meta Description:** 150-160 characters, include CTA
3. **H1:** One per page, matches search intent
4. **H2/H3:** Logical hierarchy, include secondary keywords
5. **Schema Markup:** SoftwareApplication, FAQPage, HowTo as appropriate
6. **Open Graph:** Unique image for each page
7. **Internal Links:** 3-5 contextual links per page
8. **External Links:** Link to provider docs where relevant

### Site-Wide Requirements

1. **Sitemap:** Auto-generated sitemap.xml
2. **Robots.txt:** Allow all pages
3. **Canonical URLs:** Self-referencing canonicals
4. **Page Speed:** Target <2s load time
5. **Mobile:** Responsive design (already implemented)
6. **HTTPS:** Already implemented

## Competitive Differentiation

### Key Messages to Emphasize

1. **Multi-Model Access:** "6 models, 4 providers in one plugin" - competitors typically offer 1-2 models
2. **Figma-Native:** "Never leave your design canvas" - vs. external tools requiring export/import
3. **Privacy-First:** "Your API keys stay on your device" - differentiator from subscription-based competitors
4. **BYOK Flexibility:** "Pay only for what you use" - vs. monthly subscription models
5. **Text Rendering:** "FLUX.2 and GPT-Image excel at text in images" - known weakness of Midjourney

### Competitor Gaps We Can Fill

| Competitor | Gap | Our Opportunity |
|------------|-----|-----------------|
| Midjourney | No Figma integration | Native Figma plugin |
| Leonardo.ai | Complex interface | Simplified workflow |
| Native Figma AI | Limited models | 6 models, 4 providers |
| Magician | Single model focus | Multi-model flexibility |
